# irodori-studio 要件定義書 v0.9（ドラフト）

> 正典（canonical）。本書のみ日本語、他のドキュメントは英語。
> 第1ラウンドの回答で決まった事項は **確定**、第2ラウンド未回答の事項は推奨デフォルトで **暫定** と記載する。
> 暫定・未決の一覧は §11、設計判断の根拠とステータスは `decisions.md` を参照。

---

## 1. 概要 / 目的

日本語TTSモデル **Irodori-TTS**（Aratako氏、コード・重みともMIT）の最上位チェックポイントを使う、**Windows / Mac 両対応のデスクトップ音声制作アプリ**。

- HF公式デモSpace（`Aratako/Irodori-TTS-v4.1-Small-Demo`）と、関連アプリ群（公式Irodori-TTS-Server、BOOTH版GUI、ComfyUIノード群、長文分割スクリプト等）の機能を網羅する
- 4つの用途（長文ナレーション / セリフ量産 / ボイス設計 / 他アプリ向け音声エンジン）を1本でこなす
- 構成は既存の `qwen-tts-desktop` を踏襲（Tauri 2 + Next.js + Python FastAPI sidecar + uv）【確定】
- 推論コードは upstream `Aratako/Irodori-TTS` を **コミット固定** で取り込み、改変せずアダプタ層で包む【確定】
- 作業名は `irodori-studio`。一般公開時の表示名は未定（公式アプリと誤認されない名称にする。例:「〇〇 for Irodori-TTS」）

## 3. スコープ

### 3.1 v1 対象【確定】

1. **推論層**: HF Space と公式ローカルUIの全パラメータ、LoRAアダプタの動的読み込み、Speaker Inversion埋め込み（`.speaker.safetensors`）、参照音声の事前エンコード（潜在キャッシュ）
2. **制作ツール層**: ボイスライブラリ、長文の分割・結合、台本、候補の聴き比べ、履歴・プリセット、出力形式・後処理、プロジェクト保存
3. **APIサーバー**: 外部アプリから呼べる互換API
4. **UI**: シンプル画面＋詳細パネルの二段構え。モデルでできる全機能を網羅
5. **UI言語**: 日本語・英語・中国語・ドイツ語

### 3.2 v2 以降

- 学習機能（Whisper文字起こし → 確認・修正 → manifest生成 → Speaker Inversion / LoRA学習）【確定】
- 生成後のWhisper書き起こしによる読み違い自動検出（学習機能でWhisperを導入する際に合流）【暫定】
- .docx / .pdf 入力【暫定】
- MLX推論バックエンド（v1では差し込み口のみ用意）【確定】
- Gradio互換API（ゆっくりMovieMaker4の既存Irodori連携向け）【暫定】

### 3.3 対象外

- 最上位以外のチェックポイント（旧v1〜v3、MF版、量子化版、第三者派生モデル）【確定：最上位のみ】
- Intel Mac、AMD / Intel GPU【確定】
- コード署名・公証【確定】、アプリ本体の自動アップデート（更新通知のみ）【暫定】

## 4. 動作環境

| 項目 | Windows | Mac |
| --- | --- | --- |
| OS | Windows 10 / 11（x64） | macOS 14 以降【暫定】 |
| ハードウェア | NVIDIA GPU → GPU推論。それ以外 → **CPUモード**（低速である旨を明示表示）【確定】 | Apple Silicon **M2以降**【確定】。M1は「動作保証外」の警告を出して起動は許可【暫定】 |
| メモリ | VRAM 8GB推奨。6GB以上はbf16へ自動切替、それ未満はCPUモード【暫定】 | 統合メモリ16GB推奨。8GBは動作するが低速の可能性【暫定】 |
| 推論 | PyTorch CUDA（cu128）/ CPU | PyTorch MPS（fp32）【確定】 |
| ディスク | 約15GB（実行環境 約8GB＋モデル類 約4〜5GB）＋履歴・出力 | 同左（CUDAなしのため実行環境は小さめ） |
| ネットワーク | 初回セットアップ時のみ必須。以降はオフラインで動作 | 同左 |

## 5. モデル

- 使用モデル: **Irodori-TTS-v4.1-Small**（現時点の最上位、約0.8B）＋ codec `Aratako/Semantic-DACVAE-Japanese-32dim`、チェックポイント同梱のtokenizer、SilentCipher（透かし）
- **最上位のみ**を提供する【確定】。モデル定義は registry（`sidecar/models.json`）で持ち、capability（caption対応 / speaker対応 / duration predictor / 有効パラメータ / 参照上限秒 / 推奨精度 / 必要メモリ）を記述する。UIはcapabilityから表示項目を生成する
- **Large公開時**: registryへの1件追加＋upstreamのコミット更新で対応できる設計にする【確定】。Smallは低スペック向けに併存させる【暫定】
- **保存先**: 初回ウィザードでユーザーが指定【確定】。後から変更可（既存データの移動機能つき）

## 6. 機能要件

### 6.1 画面構成【暫定】

かんたん生成 / ボイススタジオ / ナレーション / 台本 / ライブラリ・履歴 / APIサーバー / 設定

### 6.2 初回セットアップウィザード

1. 言語選択
2. 利用条件への同意（MITライセンス＋upstreamの倫理的制約：無断のなりすまし禁止、誤情報目的の利用禁止、偶然の類似の可能性、免責）
3. 環境判定（GPU / チップ / メモリ / 空き容量）と推論モードの表示
4. 保存先の指定【確定】
5. 実行環境の構築（uv → Python → 依存 → 環境に合ったtorch）
6. モデルのダウンロード（進捗表示、中断・再開、失敗時のリトライ、ログ表示）
7. 動作確認（テスト生成して再生）

2回目以降の起動では完了済みの手順をスキップする。

### 6.3 生成パラメータ（全画面共通）

- **シンプル画面**: テキスト、絵文字パレット、声（ライブラリから選択 / なし / キャプションのみ）、感情・スタイルのプリセット、生成ボタン【確定】
- **詳細パネル**: upstreamが公開する全推論パラメータ（一覧は `upstream-notes.md`）。モデルのcapabilityに応じて表示・非活性を切り替える【確定】
- 既定値はHF Spaceに準拠する
- 候補数 1〜32。候補を並べて試聴し、採用する
- シード（空欄=ランダム）。使われたシードと処理時間の内訳をログに表示

### 6.4 かんたん生成

- 1画面で「テキスト → 声 → 感情 → 生成 → 試聴 → 保存」まで完結
- 詳細パネルは折りたたみで同じ画面から開ける

### 6.5 ボイススタジオ（声の設計・保存）

- **作り方**【暫定：全部】
  - (a) キャプションで設計 → 候補から選んで保存
  - (b) 音声ファイルの取り込み（複数クリップ、合計120秒まで、推奨は30秒以上）
  - (c) アプリ内のマイク録音（例文を表示しながら30秒分を集める録音ガイド付き）
  - (d) 話者埋め込み（`.speaker.safetensors`）の取り込み
- **編集**: 波形表示、頭尻トリム、クリップ分割、クリップ順の並べ替え【暫定】。ノイズ除去はv1対象外
- **同意確認**: (b)(c)で実在の人の声を使う場合、本人同意の確認を必須とし、声データに記録する【確定】
- **声ごとの既定値**: 既定キャプション・既定パラメータ・既定シード
- **事前エンコード**: 保存時に参照潜在を計算してキャッシュする（再生成を高速化）
- 試聴用のテスト文を用意
- **共有**: 声パッケージ（参照クリップ＋既定値＋同意記録）のエクスポート / インポート【暫定】
- LoRAアダプタの登録（声に紐づけ可）

### 6.6 ナレーション（長文）

- **入力**: 貼り付け、.txt / .md、.srt【暫定】
- **前処理**: ユーザー辞書（表記 → 読みの置換、生成前に適用）、形態素解析による推定読みのプレビュー【暫定】
- **分割**: 句読点・改行を基準に、既定で80〜150字（設定可）。1回の生成上限（約30秒）を超えないこと
- **声の一貫性**: 参照音声つきの声の使用を推奨。キャプションのみの場合は「声を固定」（先頭チャンクの出力を以降の参照に使う）を提示する【暫定】
- **間**: 文末と段落で別々に無音長を設定
- チャンク単位の再生成・候補差し替え・テキスト修正
- **出力**: 結合した1本、チャンク別ファイル（任意）、SRT / VTT字幕【暫定】
- SRT入力時は、各字幕の尺に合わせて秒数を指定して生成する【暫定】
- 進捗表示、キャンセル、途中からの再開

### 6.7 台本（セリフ量産）

- 表エディタ（行：番号 / 話者 / セリフ / キャプション / 候補数 / シード / 行後の間）【暫定】
- 「話者名：セリフ」形式のテキスト貼り付けを自動解析【暫定】
- CSV / TSV の読み書き（ゲームエンジン連携用）【暫定】
- 話者 → 声（ライブラリ）の割り当て表
- 行ごとのテイク管理（候補から採用）
- **出力**: 1行1ファイル（命名テンプレート指定可、例 `{index}_{speaker}_{text_head}.wav`）＋全体を結合したドラマ音声＋字幕【暫定】

### 6.8 ライブラリ・履歴

- 全生成について、音声・全パラメータ・シード・処理時間をSQLiteに保存
- 再生、同じ条件で再生成、パラメータの流用、再エクスポート、削除
- 上限: 件数・容量で古いものから自動削除（既定500件 / 5GB、設定可）【暫定】
- プリセット（パラメータ一式）の保存・読込
- プロジェクト（ナレーション・台本）を1ファイルで保存・再開【暫定】

### 6.9 出力・後処理【暫定】

- 形式: wav / mp3 / flac / opus / aac（ffmpeg同梱）
- サンプルレート: 48kHz（モデルの出力そのまま）/ 44.1kHz
- ラウドネス正規化のプリセット（配信向け -14 LUFS、-16 LUFS、放送向け -23 LUFS）
- 話速: 既定はモデルのduration scale（自然）。正確な尺合わせ用に後処理のタイムストレッチも選択可
- 音量ゲイン
- 音程変更はv1対象外（キャプションで「低めの声」等と指定する運用）
- ファイル命名テンプレート

### 6.10 APIサーバー

- ON / OFF、ポート（既定 50221）、公開範囲（既定はlocalhostのみ。LAN公開時はAPIキー必須）【暫定】
- **OpenAI互換**（`/v1/audio/speech` ほか。Irodori固有パラメータは拡張フィールドで受け付ける）【暫定】
- **VOICEVOX互換**（`/speakers`、`/audio_query`、`/synthesis` ほか。ボイスライブラリをspeaker / styleに対応付け）【暫定】
- 合成は同時1件のキューで処理し、アプリUIと共有
- リクエストログを表示

### 6.11 設定

言語、保存先（モデル / 履歴 / プロジェクト / 出力の既定）、モデル管理（ダウンロード / 検証 / 削除 / 容量表示）、デバイス・精度、透かし、出力の既定値、履歴上限、APIサーバー、更新通知、ログ閲覧、GPU / メモリのモニタ、ライセンス表示と利用条件

### 6.12 透かし

- SilentCipherによる透かしは **既定ON、設定でOFF可**【確定】
- 参照音声を使う生成でもOFFにできるかは未決（§11 #4）

### 6.13 更新通知【暫定】

- 起動時にGitHub Releasesの最新版を確認し、新しい版があれば通知してReleasesページへ案内する
- オフライン時は何もせずスキップ。設定でOFF可

## 7. 非機能要件

| 項目 | 要件 |
| --- | --- |
| UI言語 | 日本語（基準）/ 英語 / 中国語（簡体字・暫定）/ ドイツ語。切替は即時反映。ハードコードされた表示文字列を残さない |
| 性能 | モデルは起動時に1回読み込んで常駐。2回目以降の生成は即時に開始。目安はRTX 4090級で7.8秒の音声を約1秒（40ステップ） |
| ポート | 内部APIは `127.0.0.1` のランダム空きポート。外部APIは設定値 |
| プロセス | アプリ終了時にsidecarを確実に停止（強制終了時も含む） |
| 文字コード | UTF-8で統一 |
| ログ | ファイル保存＋アプリ内で閲覧 |
| 永続化 | 設定はRust管理の `settings.json`、データはSQLite。WebViewのブラウザストレージは使わない |
| プライバシー | テレメトリなし。外部通信は初回ダウンロード・更新確認・（ユーザーが有効化した）APIのみ |
| 配布 | Windows: NSISインストーラ / Mac: dmg（arm64、ad-hoc署名）。未署名のため、初回起動の許可手順をREADMEに記載【確定】 |
| ライセンス | アプリはMIT【暫定】。同梱物（ffmpeg等）のライセンス表記を同梱 |

## 8. 倫理・安全

- 初回起動時に利用条件（upstreamの倫理的制約を含む）への同意を必須とする
- 参照音声を使う声は、本人同意の確認と記録を必須とする
- 透かしは既定ON
- 声パッケージには同意記録を含める

## 9. 受け入れ基準（抜粋）

- Windows（RTX 5090）/ GPUなしのWindows / Mac M2 の3環境で、初回ウィザードからテスト生成まで完走する
- HF Spaceの全パラメータをUIから指定でき、同じシード・同じ設定で同等の出力が得られる
- 5分以上の原稿から、声が一貫した1本の音声とSRTを出力できる
- 20行以上の台本から、行別ファイルと結合音声を出力できる
- OpenAI SDKと、VOICEVOX互換APIを使うクライアントの両方から合成できる
- 4言語すべてで、UIに未翻訳の文字列が残らない
- アプリ終了後にPythonプロセスが残らない
